## Assumptions and policies

- Dates are parsed explicitly as `DD-MM-YYYY`, the format used by the supplied file.
- `Discount_amount` is treated as a transaction-level discount amount, not a per-unit discount; the file contains one row per transaction ID, so the distinction cannot be independently confirmed from the data.
- The primary revenue metric is completed net revenue: `(quantity × unit_price) − discount_amount` for transactions whose normalized status is `completed`.
- Non-completed statuses are retained in the database but excluded from completed metrics.
- A missing `Unit_price` rejects the row because revenue cannot be calculated safely; rejected rows are reported, not silently dropped.
- A missing `Discount_amount` defaults to 0 with a warning.
- A discount greater than the transaction's gross sales is rejected as invalid because it would produce negative net revenue.
- Zero-quantity rows are retained and flagged as suspicious.
- Duplicate transaction IDs keep the first valid occurrence and reject later duplicates.
- Status values are trimmed, whitespace-collapsed, and lowercased; unknown statuses are retained as-is.
- The dataset does not specify a currency, so no currency symbol is assumed.
